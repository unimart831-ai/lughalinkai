LughaLink AI: Machine Translation of Kenyan Public Service Announcements

Few-shot NLLB transfer for English → Kiswahili & Kikuyu · DSA 4020A Natural Language Processing

Kenya · Public Information English → Kiswahili (pivot) English → Kikuyu (indigenous) NLLB-200 · Navon A100

1 · Introduction

Problem

Kenyan PSAs (health, elections, security, agriculture) are often published in English. Communities that prefer Kiswahili or indigenous languages face delayed or incomplete access to action-oriented public information.

Objective

Build a proof-of-concept MT system that translates English PSAs into Kiswahili and Kikuyu using transfer learning on a curated, framework-filtered PSA corpus.

Solution

Hybrid scrape + PSA Framework filter → 5,000 English PSAs → NLLB silver seeding → fine-tune NLLB-200 → Hub hosting + FastAPI UI for browser access.

Impact

A reproducible digital public good path: open models on Hugging Face, documented honesty about silver vs gold, and a deployable translator for demo day.

2 · Prior work & gap

  • NLLB-200 covers many African languages including Kiswahili (swh_Latn) and Kikuyu (kik_Latn).
  • Generic MT underperforms on directive PSA register (advisories, deadlines, IEBC/MoH tone).
  • Ekegusii / some targets lack reliable NLLB support → we selected Kikuyu as indigenous target.
  • Gap: few open, PSA-domain EN↔SW / EN↔Kikuyu systems with transparent data provenance.

3 · Data collection & preprocessing

  • Sources: IEBC, MoH, government / NGO sites (registry-driven scrapers).
  • Filter: PSA Framework scorer (action-oriented, public advisory tone).
  • Freeze: 5,000 English PSAs — 1,615 real + 3,385 framework-valid synthetic (labeled).
  • Sentences: 8,409 MT units from the freeze.
  • Policy: PSA-only training — OPUS / news bitext excluded.
  • Preprocess: dedupe, lang detect, glossary, train/dev/test splits.

4 · Model selection & training

  • Base: facebook/nllb-200-distilled-600M
  • Stage A: Zero-shot seed EN→SW & EN→Kikuyu (--limit 5200).
  • Stage B: Fine-tune separate checkpoints en-sw and en-kik (1 epoch).
  • Platform: Navon / Kinesis Shared · NVIDIA A100 80GB (Helsinki).
  • Key HP: LR 2e-5 · batch 4 · grad accum 4 · FP16 · max len 128.
  • Tracking: train_meta.json + experiment_log.csv.

8 · Key achievements

  • End-to-end PSA pipeline: scrape → framework filter → seed → fine-tune → eval.
  • Scaled silver bitext (~9k kept) and working EN→SW / EN→Kikuyu models.
  • Checkpoints on Hugging Face Hub (iranzi/lughalink-nllb-psa-en-*).
  • FastAPI + clean browser UI (call Hub models; no client download of weights).
  • Transparent reporting: real vs synthetic; silver vs gold.

9 · Limitations

  • Targets are machine silver until native reviewers complete human eval.
  • Synthetic English PSAs inflate volume (documented separately).
  • One-epoch few-shot fine-tune; risk of overfitting to teacher style.
  • HF free CPU Spaces may be slow; GPU preferred for demos.

10 · Future work

  • Human evaluation (fluency / adequacy / cultural accuracy).
  • Optional second model family (e.g. mT5) for comparison.
  • Richer product UI + feedback loop into gold set.
  • Expand indigenous coverage where models & data allow.

11 · Deployment & efficiency

  • Train: ~2 min / pair on A100 (1 epoch, scaled set).
  • Artifacts: ~2.3 GB / checkpoint · Hub-hosted.
  • Serve: FastAPI Space · UI at / · POST /translate.
